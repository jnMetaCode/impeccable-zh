# 项目审查与推广建议

审查日期：2026-10-09。本文由 AI 辅助审查与撰写。

## 判断

Impeccable 中文社区增强版值得继续做。最有辨识度的价值是中文排版、中文 UX 文案、国内 UI 框架指导与可维护的上游同步，而不是单纯翻译或继承上游命令数量。当前适合招募 Alpha 试用者，广泛推广前应先解决安装歧义并拿出实际改造证据。

本地 origin 已指向 `jnMetaCode/impeccable-zh`。这不证明远端公开状态或部署成功；本次 GitHub API 被环境网络限制拦截，浏览工具也未能取回项目页和 Pages 网站。个人主页已可读取，但没有展示该项目。这里需要增加项目入口，不需要把代码并入个人主页仓库。

## 已验证的基础

- `npm run localization:check` 与 `npm run localization:report` 通过：简繁体各 43/43 个跟踪源文件，分别验证 3 个中文增强文件。
- `node --test tests/localization.test.mjs tests/web.test.mjs`：23 项通过，0 失败。
- 有逐文件上游 blob 锁定、翻译合成构建、Provider 改写检查、冻结行为评测条件和拒绝无证据评分的机制。
- CI 配置包含中文构建、上游核心测试和隔离安装/更新验证；这里只检查了配置，没有验证远端运行结果。

这些证明部分构建契约与内容一致性成立，不能证明中文设计效果优于上游。本次未运行完整 Rust/Bun 套件、真实宿主安装或付费模型评测。

## 个人主页如何取舍

主页首屏保留四个主线项目：agency-agents-zh、superpowers-zh、impeccable-zh、agency-orchestrator。它们分别承担专家角色、工作方法、界面设计和协作调度，用户容易理解。

本地三件套在主页只展示 `local-agent-toolkit` 一个入口和一句用途，engram/skillet/tracelet 的安装表放回套件仓库。三个子工具继续独立维护与发布，无需为了展示合并代码。

按用户后续决定，repo-rag、orchestrator-lg、llm-gateway 暂时从个人主页项目区移除，保留仓库，不删除、不归档、不转私有。推广投入优先用于 impeccable-zh 和 local-agent-toolkit。以后有实际使用案例再恢复展示。`7/7`、`10/10` 是测试计数，不能单独代表生产成熟度；RAG 指标应连同数据集范围和测量条件展示。

建议置顶：四个主线项目 + local-agent-toolkit + ai-coding-guide。作品和课程保留简短入口，详细目录放到对应仓库/网站。

主页现有插件文案需要纠正：`/plugin marketplace add` 只是添加市场，套件 README 还要求 `/plugin install local-agent-toolkit@local-agent-toolkit`。tracelet 还需要启动终端服务与接入 tracing；不能暗示打开面板就自动捕获所有 Agent。`npx` 会下载/缓存包，“无需手动全局安装”比“不在电脑里装东西”准确。

## 推广执行顺序

1. **准备期**：统一中文安装路径，完成一个真实可复核的前后案例，确认公开仓库与 Pages 可访问。
2. **第一周**：在个人主页主线添加 impeccable-zh，并置顶；在 superpowers-zh、agency-agents-zh 的相关设计场景增加自然的交叉链接。先完成一次完整安装再宣传命令。
3. **第二周**：公众号、视频号或抖音发布同一个 60–90 秒案例：“AI 生成的中文后台，怎样修好标签换行、手机布局和错误状态”。内容展示具体问题、操作与结果，结尾只保留一个项目入口。
4. **第三至四周**：在允许项目分享的中文开发者社区发布技术复盘；邀请 5–10 位试用者按统一模板反馈工具版本、安装结果、页面类型与问题。不要群发广告。
5. **复盘**：记录安装成功数、完成首个设计任务数、有效反馈数、重复使用情况，并参考仓库访问/克隆数据。Stars 是辅助指标；不必为衡量推广先加遥测。

推荐内容主题：“同一个 Element Plus 表单，改造前后有什么差别”“中文设计 Skill 与中文回答的区别”“设计命令如何和 superpowers 工作流配合”。这些内容必须基于实际运行产物。
