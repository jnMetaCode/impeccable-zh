# 中文 UX 文案增強

> 來源型別：`jnMetaCode-original`。
> 適用命令：`clarify`、`harden`。

通用 UX 寫作規則之外，中文產品必須額外檢查以下問題。

## 按鈕與操作

- 優先使用“動詞 + 物件”：`儲存草稿`、`刪除成員`、`提交稽核`。
- 上下文已經明確物件時可以只保留動詞：表單底部的 `儲存`。
- 避免含義不完整的 `確定`、`提交`、`處理`、`操作`。
- 同一個動作不要混用 `新建`、`建立`、`新增`；根據產品術語選擇一個並保持一致。
- 按鈕文案描述結果，不描述點選動作。使用 `下載報告`，不使用 `點選下載`。

## 錯誤與恢復

錯誤資訊按“發生了什麼 + 使用者能做什麼”組織：

```text
無法儲存修改。網路連線已中斷，請恢復網路後重試。
```

避免：

- `操作失敗`：沒有說明失敗物件；
- `系統繁忙，請稍後再試`：系統無法確認原因時不要假裝知道；
- `參數錯誤`：把內部實作語言直接交給使用者；
- `未知錯誤`：沒有恢復路徑；
- 把完整異常、堆疊、請求 ID 當作主要資訊。

請求 ID 可以放在“錯誤詳情”中，供支援人員使用。

## 高風險確認

刪除、支付、釋出、轉賬、權限變更和退出組織必須說明：

1. 操作物件；
2. 是否可恢復；
3. 立即生效還是延遲生效；
4. 使用者下一步需要做什麼。

```text
刪除“華東銷售組”？
該小組及其未匯出的報表將永久刪除，無法恢復。

[取消] [刪除小組]
```

不要使用：

```text
確認執行此操作嗎？
[否] [是]
```

## 金額、日期與數量

- 金額必須明確幣種；跨幣種場景不要只顯示 `¥`。
- 千分位、小數位和負數格式使用 locale formatter，不能拼接字串。
- `今天`、`剛剛` 等相對時間需要可訪問的絕對時間或詳情。
- 有時區影響的操作明確顯示時區。
- 中文通常不依賴名詞複數，但數量單位和量詞仍需符合語境。
- 不把 `1.2k`、`3m` 等英文縮寫機械帶入正式中文業務介面。

## 空狀態

先區分空狀態原因：

- 首次使用：解釋價值並提供建立入口；
- 搜尋無結果：展示查詢條件並允許清除；
- 篩選後無資料：提供重置篩選；
- 無權限：說明需要什麼權限和申請路徑；
- 載入失敗：展示重試或替代路徑；
- 資料確實為空：不偽裝成錯誤。

避免所有場景都使用“暫無資料”。

## 避免翻譯腔

- `瞭解更多關於此功能的資訊` → `瞭解此功能`
- `你的更改已被成功儲存` → `修改已儲存`
- `你確定你想要繼續嗎？` → 根據實際後果重寫
- `發生了一個錯誤` → 說明失敗物件和恢復方式
- `請輸入您的使用者名稱` → 語境允許時使用 `輸入使用者名稱`

不要為了口語化刪除事實，也不要把嚴肅風險寫成玩笑。

## 驗證樣例

至少使用以下動態內容檢查介面：

- 20 字以上的中文姓名或組織名；
- `新疆維吾爾自治區` 等長地區名；
- `人民幣 1,234,567.89 元`；
- 包含英文產品名、版本號和中文單位的句子；
- 0、1、2、10,000 等數量邊界；
- 失敗、無權限、處理中、部分成功和需要人工稽核狀態；
- 繁體中文、繁體中文和英文切換後的佈局。

最終文案必須經完整流程閱讀，不能只在字串列表裡逐項潤色。
