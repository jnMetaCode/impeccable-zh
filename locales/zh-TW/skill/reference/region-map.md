# 區域對映

區域對映在資源生產前，為已批准設計稿中實際可見的內容命名。它不是頁面建置，也不是資源審批。

1. 執行 `{{scripts_path}}/impeccable comp-spec --comp <comp.png> --grid`，開啟原圖和網格圖。
2. 執行 `{{scripts_path}}/impeccable comp-spec --schema` 檢視 JSON 欄位。編寫包含 `regions` 陣列的 `regions.json`。每個區域需要穩定的 `id`、`kind`、`note`，並且只能包含 `pixelBox`、歸一化 `box` 或 `grid` 之一。使用原始設計稿尺寸。
3. 執行 `{{scripts_path}}/impeccable comp-spec --comp <comp.png> --regions regions.json --inspect-map`。輸出會指向報告、疊加圖、精確裁剪圖和帶遮罩參考的 `COMPARE` 對比圖。預設輸出發現；`--json` 輸出完整報告，對比圖路徑位於 `comparisonSheets`。
4. 先開啟對比圖，一起檢查受影響裁剪，再按需開啟單張裁剪檢視細節。將邊界與原圖比較，同時檢查被排除的前景畫素和幾何錯誤。每個相互重疊的非容器程式碼框都會被完整遮罩，包括框內空白。分別框選獨立文字元素，讓間隙中的圖稿保持可見；容器只描述佈局範圍，絕不能替代其子項。修正對映並重新檢查，每輪使用新的輸出目錄。零錯誤不代表裁剪一定準確。覆蓋率警告只是提示，不是完整性的證明。

如果請求止於對映，輸出對映、檢查報告和未解決發現後停止。若繼續建置，使用 `comp-spec --comp <comp.png> --regions regions.json` 測量已檢查對映，並遵循 [new-work.md](new-work.md)。

`--auto` 只產生水平分割槽骨架，不識別元素。它是可選輔助，不能代替人工編寫對映。

## 包含關係

`parentId` 指向一個帶有 `container: true` 的包圍區域。父項與子項保留各自 ID 和裁剪圖。包含關係絕不傳遞審批結果。

## 獨立變化的內容

按照可以獨立變化的內容拆分割槽域：網站會替換的內容（房間照片、商品、人物）、運動部件（hover 或標誌性互動會移動的物件）和結構（框架、圍邊、裝飾）。一扇開啟百葉窗、能看到房間的窗戶包含三類區域：帶透明開口的外框 plate、其下方作為 image 區域的房間，以及每片獨立的百葉窗 plate。重疊區域在頁面中合成。`comp-spec` 會標記 note 同時描述框架及其所開啟視野的柵格區域（`baked-composite`），計劃與資源評審會優先展示它。

## 繪製材質

測量時，`comp-spec` 會標記裁剪結果像繪製內容（`painted-pixels`：顏色豐富、漸變柔和）的 `text`、`control` 或 `chrome` 區域，包括容器，並在摘要中列出。計劃與資源評審會優先展示這些區域，以及標為 `codeDrawn` 的區域（你選擇用程式碼繪製的材質）。不要把識別責任留給使用者：如果區域是繪製材質，如人物、照片、金屬或紙張表面，現在就將它歸類為 `plate`、`image` 或 `texture`。

設計稿裁剪只能作為參考證據，絕不能用作生產資源。對映檢查器會將其 PNG 標記為來自設計稿。
