> **還需要補充的上下文**：希望使用者抵達的“頓悟時刻”，以及使用者的經驗水平。

儘快讓使用者第一次獲得價值。新手引導的職責不是教授整個產品，而是帶使用者抵達那個足以證明產品值得投入時間的時刻。

## 評估新手引導需求

理解使用者需要學習什麼，以及為什麼需要學習：

1. **識別挑戰**：
   - 使用者想完成什麼？
   - 目前體驗中哪些地方令人困惑或不清楚？
   - 使用者會在哪裡卡住或流失？
   - 希望使用者抵達哪個“頓悟時刻”？

2. **理解使用者**：
   - 他們的經驗水平如何？（新手、熟練使用者，還是兩者都有？）
   - 他們的動機是什麼？（興奮地探索，還是工作要求？）
   - 他們願意投入多少時間？（5 分鐘，還是 30 分鐘？）
   - 他們瞭解哪些替代方案？（從競品遷移，還是第一次接觸這個品類？）

3. **定義成功**：
   - 使用者至少需要學會什麼才能成功？
   - 希望他們完成哪個關鍵操作？（建立第一個專案，還是發出第一次邀請？）
   - 如何判斷新手引導有效？（完成率，還是首次價值時間？）

**關鍵要求**：新手引導應讓使用者儘快獲得價值，而不是儘可能教完所有內容。

## 新手引導原則

遵循以下核心原則：

### 展示，而不是講解
- 使用可執行的示例示範，而不只是描述
- 在新手引導中提供真實功能，而不是單獨的教程模式
- 使用漸進披露，一次只教一件事

### 儘可能允許跳過
- 讓有經驗的使用者跳過新手引導
- 不要阻止使用者進入產品
- 提供“跳過”或“我自己探索”選項

### 首次價值時間
- 儘快讓使用者抵達“頓悟時刻”
- 優先呈現最重要的概念
- 教會能帶來 80% 價值的 20% 內容
- 將高階功能留到相關場景中再介紹

### 情境優先於儀式
- 在使用者需要時教授功能，而不是一開始全部講完
- 空狀態就是新手引導機會
- 在使用位置提供工具提示和引導

### 尊重使用者的理解力
- 不要居高臨下或過度解釋
- 保持簡潔清楚
- 假設使用者能夠理解標準互動模式

## 設計新手引導體驗

根據實際情境建立合適的引導：

### 產品首次引導

**歡迎頁面**：
- 清晰的價值主張（這是什麼產品？）
- 使用者將學會或完成什麼
- 誠實的時間預估
- 為有經驗的使用者提供跳過選項

**賬戶設定**：
- 只收集必需資訊，其他內容稍後再收集
- 解釋為什麼需要每一項資訊
- 儘可能提供合理預設值
- 在適當場景提供第三方賬號登入

**核心概念介紹**：
- 介紹 1～3 個核心概念，而不是全部內容
- 使用簡單語言和示例
- 儘可能讓使用者動手操作，而不是隻閱讀
- 顯示進度，例如“第 1 步，共 3 步”

**第一次成功**：
- 引導使用者完成一件真實的事情
- 提供預填充示例或模板
- 慶祝完成，但不要過度
- 給出清晰的下一步

### 功能發現與採用

**空狀態**：
不要只留下空白，而應展示：
- 這裡將出現什麼（說明與截圖或插圖）
- 它為什麼有價值
- 建立第一項內容的清晰行動按鈕
- 示例或模板選項

示例：
```
還沒有專案
專案可以幫助你組織工作並與團隊協作。
[建立第一個專案] 或 [從模板開始]
```

**情境式工具提示**：
- 在合適時機出現，例如使用者第一次看到該功能時
- 直接指向相關介面元素
- 提供簡短說明和收益
- 可以關閉，並提供“不再顯示”選項
- 可選的“瞭解更多”連結

**功能公告**：
- 新功能釋出時突出顯示
- 說明新增了什麼，以及為什麼重要
- 讓使用者能夠立即嘗試
- 可以關閉

**漸進式引導**：
- 在使用者遇到功能時再講解
- 為新增或未使用的功能提供徽標或標記
- 逐步開放複雜度，不要立刻展示所有選項

### 引導式導覽與分步示範

**適用場景**：
- 功能眾多的複雜介面
- 現有產品發生重大變化
- 需要行業領域知識的專業工具

**設計方式**：
- 聚焦特定介面元素，並調暗頁面其他部分
- 保持步驟簡短，每次導覽最多 3～7 步
- 允許使用者自由前後瀏覽步驟
- 提供“跳過導覽”選項
- 可從幫助選單重新播放

**最佳實踐**：
- 互動優先於被動觀看，讓使用者點選真實按鈕
- 聚焦工作流而不是功能，例如“建立專案”而不是“這是專案按鈕”
- 提供示例資料，確保操作能夠真正執行

### 互動式教程

**適用場景**：
- 使用者需要動手練習
- 概念複雜或陌生
- 風險較高，適合先在安全環境中練習

**設計方式**：
- 提供帶示例資料的沙盒環境
- 給出清晰目標，例如“建立一張按地區展示銷售額的圖表”
- 提供分步指導
- 驗證使用者是否正確完成
- 設定明確的結業時刻，例如“你已經準備好了！”

### 文件與幫助

**產品內幫助**：
- 在整個介面中提供情境式幫助連結
- 提供鍵盤快捷鍵參考
- 提供可搜尋的幫助中心
- 為複雜工作流提供影片教程

**幫助模式**：
- 在複雜功能附近放置 `?` 圖示
- 在工具提示中提供“瞭解更多”連結
- 顯示鍵盤快捷鍵提示，例如在搜尋框中顯示 `⌘K`

## 空狀態設計

每個空狀態都需要包含：

### 這裡將出現什麼
“你最近的專案會顯示在這裡”

### 為什麼重要
“專案可以幫助你組織工作並與團隊協作”

### 如何開始
[建立專案] 或 [從模板匯入]

### 視覺吸引力
使用插圖或圖示，而不是隻在空白頁面上放文字

### 情境式幫助
“需要入門幫助？[觀看 2 分鐘教程]”

**空狀態型別**：
- **首次使用**：從未使用過此功能，應強調價值並提供模板
- **使用者已清空**：使用者主動刪除了全部內容，應輕量提示並方便重新建立
- **沒有結果**：搜尋或篩選沒有返回內容，應建議其他關鍵詞或清除篩選條件
- **沒有權限**：無法訪問，應解釋原因和獲取權限的方法
- **錯誤狀態**：載入失敗，應解釋發生了什麼並提供重試選項

## 實作模式

### 技術方案：

**工具提示庫**：Tippy.js、Popper.js
**導覽庫**：Intro.js、Shepherd.js、React Joyride
**模態框模式**：焦點約束、背景遮罩、按 ESC 關閉
**進度記錄**：使用 LocalStorage 儲存“已看過”狀態
**資料分析**：記錄完成率和流失位置

**儲存模式**：
```javascript
// 記錄使用者已經看過哪些新手引導步驟
localStorage.setItem('onboarding-completed', 'true');
localStorage.setItem('feature-tooltip-seen-reports', 'true');
```

**重要要求**：不要重複展示同一套新手引導，這會令人厭煩。記錄完成狀態並尊重使用者的關閉操作。

**絕對不要**：
- 強迫使用者完成很長的新手引導後才能使用產品
- 用顯而易見的解釋輕視使用者
- 反覆顯示同一個工具提示，必須尊重關閉操作
- 在導覽期間阻塞整個介面，應允許使用者探索
- 建立與真實產品脫節的獨立教程模式
- 一開始就塞入過多資訊，應使用漸進披露
- 隱藏“跳過”或故意讓它難以找到
- 忘記回訪使用者，不要再次展示首次引導

## 驗證新手引導品質

與真實使用者一起測試：

- **完成時間**：使用者能否快速完成引導？
- **理解程度**：完成後使用者是否真正理解？
- **後續行動**：使用者是否執行了期望的下一步？
- **跳過率**：是否有太多使用者跳過？也許引導太長或缺乏價值
- **完成率**：使用者是否完成？如果完成率低，應進一步簡化
- **首次價值時間**：使用者需要多久才能第一次獲得價值？

當使用者能迅速抵達頓悟時刻且沒有中途流失時，交給 `{{command_prefix}}impeccable polish` 完成最終精修。
