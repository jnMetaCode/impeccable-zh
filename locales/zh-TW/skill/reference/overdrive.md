響應必須以下列內容開頭：

```
──────────── ⚡ OVERDRIVE ─────────────
》》》 Entering overdrive mode...
```

把介面推向常規邊界之外。這不只是新增視覺效果，而是充分利用瀏覽器能力，讓介面的任何部分都顯得非凡：能處理百萬行的表格、從觸發按鈕形變而來的對話方塊、用流式回饋即時校驗的表單，或具有電影感的頁面轉換。

**本命令格外重要的原則**：上下文決定“非凡”的含義。作品集上的粒子系統可能令人驚豔，設定頁面上的同一效果卻會令人尷尬；但設定頁面如果擁有即時樂觀儲存和動畫狀態轉換，同樣可以非凡。決定方案前先理解專案個性和目標。

### 建置前先提出方案

本命令最容易方向失誤。絕不要直接實作。必須：

1. **思考 2～3 個不同方向**：考慮不同技術、野心程度和審美方式；簡要說明每個方向最終的觀感。
2. **寫程式碼前取得使用者選擇。** {{ask_instruction}} 每個選項本身必須包含方向說明和取捨（瀏覽器支援、效能成本、複雜度），讓使用者能閱讀後選擇。結構化問題會阻塞同一條訊息，直到使用者回答；與問題並列編寫的方向在選擇期間不可見。
3. 只實施使用者確認的方向。

跳過這一步可能建置出令人尷尬、只能丟棄的結果。

### 使用瀏覽器自動化迭代

技術上有野心的效果幾乎不會第一次就正確。必須主動使用瀏覽器自動化預覽、視覺驗證並迭代。不要假設效果正確，要親自檢查，並預期多輪精修。“技術可執行”和“視覺非凡”之間的差距只能透過視覺迭代彌合，不能只靠程式碼。

## 判斷這裡的“非凡”是什麼

正確的技術野心完全取決於目前物件。選擇技術前先問：**什麼會讓這個特定介面的使用者說“哇，真不錯”？**

### 視覺或營銷介面
頁面、Hero、著陸頁和作品集的驚豔通常來自感官體驗：滾動驅動揭示、著色器背景、電影式頁面轉換、響應游標的產生藝術。

### 功能型介面
表格、表單、對話方塊和導航的驚豔在於操作感受：透過 View Transitions 從按鈕形變而來的對話方塊、藉助虛擬滾動以 60fps 渲染十萬行的資料表、近乎即時的流式校驗、具有彈簧物理效果的拖放。

### 效能關鍵介面
驚豔不可見但可以感受：搜尋五萬項仍毫無閃爍、複雜表單從不阻塞主執行緒、近即時處理的圖片編輯器。介面從不遲疑。

### 資料密集介面
圖表與儀表盤的驚豔來自流動性：Canvas/WebGL GPU 渲染海量資料、資料狀態之間的動畫轉換、自然穩定的力導向圖。

**共同點**：實作超出使用者對 Web 介面的預期。技術服務於體驗，而不是反過來。

## 工具箱

按目標組織，而不是按技術名稱組織。

### 讓轉換具有電影感
- **View Transitions API**（同文檔：全部瀏覽器；跨文件：Firefox 不支援）：狀態間共享元素形變，例如列表項展開成詳情頁、按鈕變為對話方塊；最接近原生 FLIP 動畫。
- **`@starting-style`**（全部瀏覽器）：只用 CSS 讓元素從 `display: none` 進入可見狀態，包括入場關鍵幀。
- **彈簧物理**：使用品質、張力和阻尼，而不是 cubic-bezier。可使用 motion（原 Framer Motion）、GSAP 或自行實作彈簧求解器。

### 將動畫繫結到滾動位置
- **滾動驅動動畫**（`animation-timeline: scroll()`）：純 CSS，無需 JS。視差、進度條和揭示序列由滾動位置驅動。（Chrome/Edge/Safari；Firefox 僅 flag；始終提供靜態回退）

### 超越 CSS 渲染
- **WebGL**（全部瀏覽器）：著色器、後處理和粒子系統。可使用 Three.js、輕量 OGL、regl。
- **WebGPU**（Chrome/Edge；Safari 26+；Windows/macOS 上的 Firefox，Linux/Android Firefox 僅 flag）：新一代 GPU 計算，能力強於 WebGL。始終回退到 WebGL2。
- **Canvas 2D / OffscreenCanvas**：自定義渲染、畫素處理，或透過 Web Worker + OffscreenCanvas 把繁重渲染移出主執行緒。
- **SVG filter chain**：用 displacement map、turbulence、morphology 實作有機扭曲，且可由 CSS 動畫化。

### 讓資料鮮活
- **虛擬滾動**：數萬項表格或列表只渲染可見行。簡單情況無需庫，複雜情況使用 TanStack Virtual。
- **GPU 加速圖表**：為大到無法用 SVG/DOM 渲染的資料集使用 Canvas 或 WebGL，可使用 deck.gl 或基於 regl 的自定義渲染器。
- **資料轉換動畫**：在圖表狀態間形變，而不是直接替換。使用 D3 `transition()` 或面向 DOM 圖表的 View Transitions。

### 動畫化複雜屬性
- **`@property`**（全部瀏覽器）：註冊有型別的 CSS 自定義屬性，讓漸變、顏色和複雜值可以插值動畫。
- **Web Animations API**（全部瀏覽器）：用 JavaScript 驅動、具備 CSS 效能的動畫，可組合、取消和反向，是複雜編排的基礎。

### 突破效能邊界
- **Web Worker**：把資料處理、圖片操作和搜尋索引等繁重計算移出主執行緒。
- **OffscreenCanvas**：在 Worker 執行緒渲染，讓複雜視覺執行時主執行緒仍保持空閒。
- **WASM**：為圖片處理、物理模擬和編解碼等計算密集功能提供接近原生的效能。

### 與裝置互動
- **Web Audio API**：空間音訊、音訊響應視覺和聲音回饋，需要使用者手勢後啟動。
- **裝置 API**：方向、環境光和地理位置。謹慎使用，始終取得使用者許可。

**注意**：本命令增強介面的感受，不改變產品功能。即時協作、離線支援和新後端能力屬於產品決策，不是 UI 增強。聚焦於讓現有功能顯得非凡。

## 有紀律地實作

### 漸進增強不可妥協

每項技術都必須優雅降級。沒有增強效果時，體驗仍然必須良好。

```css
@supports (animation-timeline: scroll()) {
  .hero { animation-timeline: scroll(); }
}
```

```javascript
if ('gpu' in navigator) { /* WebGPU */ }
else if (canvas.getContext('webgl2')) { /* WebGL2 fallback */ }
/* CSS-only fallback must still look good */
```

### 效能規則

- 目標為 60fps；低於 50 時簡化。
- WebGL context、WASM module 等繁重資源只在接近視口時延遲初始化。
- 暫停視口外渲染；看不見的內容應停止執行。
- 在真實中端裝置上測試，而不只是在開發機器上。

### 精修決定差異

“酷”和“非凡”之間的差距在最後 20% 的精修：彈簧動畫的緩動曲線、錯峰揭示的時間偏移、讓轉換具有物理感的細微輔助運動。不要釋出第一個可執行版本，要釋出感覺順理成章的版本。

**絕對不要**：
- 釋出會讓中端裝置卡頓的效果
- 使用前沿 API 卻不提供可用回退
- 未經使用者明確同意新增聲音
- 用技術野心掩蓋薄弱的設計基礎，應先用其他命令修復基礎
- 疊加多個相互競爭的非凡時刻；聚焦創造影響力，過量製造噪音

## 驗證結果

- **驚豔測試**：展示給未看過的人，他們有反應嗎？
- **移除測試**：去掉效果後，體驗是否明顯減弱，還是無人察覺？
- **裝置測試**：在手機、平板和 Chromebook 上執行，仍然流暢嗎？
- **情境測試**：它符合這個品牌和受眾嗎？

“技術上非凡”不是使用最新 API，而是讓介面做到使用者原以為網站做不到的事情。
