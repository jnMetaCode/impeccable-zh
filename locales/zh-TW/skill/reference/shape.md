# Shape

先弄清應該做什麼以及它應該如何工作，再輸出一份經過確認且不包含程式碼的設計簡報。

## 階段 1：探索訪談

此時不要編寫程式碼，也不要選擇視覺方向。

### 訪談節奏

- 有結構化提問工具時使用該工具，否則提問後停止並等待。
- 每輪詢問兩到三個相關問題，然後等待回答。預設只進行一輪；只有回答暴露出實質缺口時才增加第二輪。
- 不要一次丟擲整份問卷、重複已經確定的事實，或把顯而易見的事實變成選項。直接陳述最可能的理解，並邀請使用者糾正。
- 資訊稀少的請求至少需要一輪迴答。非常精確的請求可能只需一次簡短確認。

### 第 1 輪：目的、使用者與結果

選擇最可能改變結果的兩到三個問題：

- 這個介面或功能有什麼用途，必須解決什麼問題？
- 具體哪些人會來到這裡？他們處於什麼情境和心理狀態？
- 他們最需要理解或完成什麼？成功是什麼樣子？
- 這裡有哪些事實是相鄰產品或通用模板無法聲稱的？

### 第 2 輪：素材、行為與邊界

僅在仍有重大決策未解決時進行：

- 體驗必須承載哪些真實內容、證據、資料和資源？現實的最小、典型和最大範圍分別是多少？
- 哪些狀態和轉換很重要：首次使用、空、載入、錯誤、成功、權限、溢位，還是專家使用？
- 預期的保真度、廣度和互動性是什麼：探索、可投產頁面、完整流程，還是更廣的介面範圍？
- 哪些內容必須保持不變？即使視覺精美，出現什麼仍會讓結果感覺錯誤？
- 哪些平臺、框架、效能、無障礙、在地化或交付約束具有強制性？

絕不要詢問 CSS 數值或套裝式審美路線。視覺世界和概念選擇屬於 New-work。

## 階段 2：確定設計方向

對於新介面、品牌擴充功能或替換，按照 [new-work.md](new-work.md) 完成視覺主導方向、必要的世界觀工作坊和概念選擇。複用探索結果，然後在進入契約、持久化或實作之前返回。在已有視覺世界中，只有當構圖或互動仍有實質性開放空間時，才使用其中的概念流程。

## 階段 3：編寫簡報

編寫儘可能精簡且有用的簡報：

1. **任務與受眾：** 誰會到達這裡，他們的情境、需求和訪客模式是什麼。
2. **結果與證據：** 主要任務或操作、成功標準、真實證據和產品特有事實。
3. **選定方向：** 視覺主導方向、結構或互動主張、順序、焦點時刻及其實作影響。
4. **範圍與邊界：** 保真度、廣度、互動性、明確目標、必須保持不變的部分和顯式反目標。
5. **狀態與範圍：** 現實的內容或資料範圍，以及重要狀態。
6. **互動與佈局：** 層級、拓撲、回應式、可供性、回饋和轉換；描述意圖，而不是 CSS。
7. **約束與開放決策：** 平臺、交付、無障礙、在地化、可複用元件，以及建置者不得自行發明的選擇。

任務已經明確時使用三到五個要點；只有面對模糊、多頁面或獨立規劃任務時才使用完整結構。不要重複複述對話。

## 確認並停止

提交簡報以獲得明確確認，或進行一輪修正，然後停止：shape 絕不編寫程式碼或方向契約。

當沒有人工回答或結構化回答機制時，清楚標記假設，返回簡報，然後停止。
