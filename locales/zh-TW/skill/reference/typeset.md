排版承載資訊、層級和語氣。應在已經確立的視覺體系內改善排版；除非使用者明確要求，否則不要藉機替換產品身份。

## 訪客模式

- **說服 + 體驗：** 展示字型可以承擔品牌聲音。在構圖需要時，使用明確對比和回應式字號。
- **操作 + 閱讀：** 穩定、可掃描和合適行長優先。一個精心調整的字型家族和固定角色級別通常已經足夠。
- **原生應用：** 遵循 [ios.md](ios.md) 或 [android.md](android.md)，包括平臺字號縮放和無障礙行為。

如果更換字型會產生新的產品身份，應進入 [new-work.md](new-work.md) 並更新 DESIGN.md；否則保留已經確認的字型家族，只改善使用方式。

## 兩項隔離評估

如果存在並允許使用子 Agent，獨立執行以下兩項評估；否則按順序自行完成。不要讓偵測器結果預先影響設計判斷。

1. **排版評估：** 檢查代表性頁面和樣式。下面每個問題都必須用檔案、選擇器或計算值回答：
   - **權威與調整：** 目前確定了哪些字型、字重和角色？它們是否適合產品和選定視覺體系，還是未經檢查的預設值？每個字型家族是否都有必要？
   - **層級：** 標題、正文、標籤、元資料和資料角色能否一眼區分？相鄰字號或字重是否過於接近，無法承擔不同職責？
   - **尺度與一致性：** 是否存在明確的角色級別，還是任意值的集合？同一角色在不同頁面與狀態中是否一致？
   - **閱讀：** 正文是否保持舒適的 45～75 字元行長？行高、段落節奏、對比度和字間距是否針對實際字型、寬度、語言和介面調整？
   - **壓力情況：** 長標題、在地化文字擴張、頁面縮放、窄容器、缺失字重和字型回退時會發生什麼？
   - **交付：** 是否只加載真正使用的字型資源？回退字型指標、載入策略和可變字型設定能否避免不可見文字與明顯佈局偏移？
2. **機械掃描：** 執行：

```bash
{{scripts_path}}/impeccable detect --json --scope type [target files or dirs]
```

還要檢查偵測器無法解釋的動態或任意字型值。編輯前綜合兩項評估，並說明各自單獨發現了什麼。掃描無問題只是底線，不代表排版優秀。

## 建立系統

編輯前明確：

- 介面需要哪些角色；
- 各角色之間需要怎樣的對比；
- 閱讀行長和資訊密度；
- 哪些現有字型與字重具有權威性；
- 效能、在地化和無障礙約束。

使用能夠清晰表達層級的最少角色和字型家族。綜合使用字號、字重、空間和色調，不要只靠字號承擔全部層級。

## 應用

- 正文必須舒適可讀並支援縮放。普通網頁正文以 1rem / 16px 為下限，除非高密度角色、平臺習慣或使用者設定提供充分理由。
- 正文行長控制在 45～75ch。根據行長反向調整行高：行越寬，通常越需要更大行距。
- 深色背景上的淺色文字應同時從三個感知維度補償：略增行高、略增字間距，並在字型需要時增加一級字重。
- 按具體字型、寬度、語言和對比度調整行高，不套用統一比例。
- 同一角色在不同頁面和狀態中保持一致。
- 數字、表格、程式碼和標籤內容適合時使用對應 OpenType 特性。
- 只加載實際使用的字型和字重。提供指標相容的回退字型，避免阻塞文字顯示。
- 營銷展示字型可根據空間回應式變化；高密度產品和閱讀介面應保持空間穩定。
- 保留瀏覽器縮放、使用者字型設定、Dynamic Type 和平臺文字縮放能力。
- 使用段落間距或首行縮排作為主要段落節奏；同時使用通常會重複標記邊界。

不要為了裝飾犧牲可理解性；沒有隻有第二字型才能承擔的明確角色時，不要引入新的字型家族。

## 驗證

- 主要、次要、正文和元資料角色無需閱讀內容就能區分。
- 長文字在相關寬度和語言下仍然舒適。
- 排版屬於該產品及其既有視覺體系。
- 字型載入不會造成明顯重排或不可見文字。
- 縮放、文字縮放、焦點、對比度和窄視口路徑保持可用。
- 最終機械掃描沒有無法解釋的發現。

每項都必須提供渲染或原始碼證據，然後重新掃描。不能用簡單的“是”代替驗證。

層級穩定後，交給 `{{command_prefix}}impeccable polish`。

## 即時模式簽名參數

每個變體宣告一個粗粒度 `scale` 參數，並圍繞 `var(--p-scale, 1)` 編寫字號級別。

```json
{"id":"scale","kind":"range","min":0.85,"max":1.3,"step":0.05,"default":1,"label":"Scale"}
```

只有在真實代表系統選擇時，最多再增加一個字型組合或字重參數。遵循 [live.md](live.md) 的參數契約。
