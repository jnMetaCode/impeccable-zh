對原生應用（`ios` / `android` / `adaptive`）執行系統化的**技術**品質檢查，並產生完整報告。不要修復問題；記錄問題，交給其他命令處理。

這是程式碼級稽核，不是設計評審。從原始碼（SwiftUI / UIKit / Compose / React Native / Flutter）稽核；瀏覽器工具和 `impeccable detect` 均不適用。按照平臺參考評分： [ios.md](ios.md) / [android.md](android.md)，`adaptive` 同時使用兩者。如果 Setup 尚未讀取，評分前先讀取。報告骨架與 [audit.md](audit.md) 對齊；修改時保持同步。

## 診斷掃描

全面檢查 5 個維度，並按以下標準分別評分 0～4。

### 1. 無障礙（VoiceOver / TalkBack）

**檢查**：
- **缺少標籤**：互動元素沒有無障礙標籤、trait/role 或狀態播報
- **閱讀與焦點順序**：遍歷不合邏輯、控制元件不可達、導航後焦點丟失
- **文字縮放**：固定 point 破壞 Dynamic Type（iOS），或使用 px 而非 sp（Android）；大字號時佈局裁切或重疊
- **觸控目標**：小於 44 pt（iOS）/ 48 dp（Android），或間距過小
- **忽略 Reduce Motion**：視差和大幅滑動沒有交叉淡化替代
- **對比度**：淺色或深色外觀中文字對比度不達標

**評分 0～4**：0=螢幕閱讀器不可用；1=重大缺口；2=部分支援但順序或縮放失效；3=良好，僅少量問題；4=優秀，標籤、順序、縮放和 Reduce Motion 均完整

### 2. 效能

**檢查**：
- **啟動緩慢**：首幀前執行繁重工作
- **列表未虛擬化**：長內容沒有 FlatList / LazyColumn / List 複用
- **主執行緒卡頓**：滾動或手勢路徑執行同步工作，在 60/120 Hz 下掉幀
- **浪費渲染**：React Native 不必要重渲染或 Compose 不必要重組；缺少 memoization/key
- **圖片處理**：縮圖解碼完整尺寸圖片，且沒有快取
- **應用體積**：JS bundle 或二進位制臃腫，存在未使用依賴

**評分 0～4**：0=處處卡頓；1=重大問題；2=部分達標；3=良好，可小幅改進；4=優秀，啟動快、滾動順、體積精簡

### 3. 外觀與主題

**檢查**：
- **硬編碼顏色**：使用原始 hex，而不是語義系統色（iOS）、Material 色彩角色（Android）或設計 token
- **深色外觀損壞**：缺少深色變體、深色對比度差或簡單反色
- **Dynamic Color**（Android 12+）：缺少靜態回退，或適合使用時被忽略
- **偏離平臺的材質**：應該使用系統 material 或色調層級時自行實作視覺材質

**評分 0～4**：0=全部硬編碼；1=幾乎沒有 token；2=有 token 但使用不一致；3=良好，僅少量硬編碼；4=優秀，全程語義化且兩種外觀均為一等方案

### 4. 平臺一致性（關鍵）

依據已載入的平臺參考及其粗糙感測試評分。**檢查**：
- **系統手勢損壞**：停用 iOS 邊緣返回，或劫持 Android predictive Back
- **違反 inset**：內容位於劉海、靈動島、Home 指示條、狀態列或鍵盤下方
- **偏離平臺的導航**：自定義全域性導航、過載 tab bar、跨平臺照搬模式
- **Web 形態控制元件**：HTML 式按鈕、自定義開關、依賴 hover 的可供性
- **圖示漂移**：混合圖示集，而不是 SF Symbols / Material Symbols
- **系統漂移**：重複捷徑或裝飾模式與產品、平臺或既有設計系統衝突

**評分 0～4**：0=純 Web 移植；1=嚴重違反 3～4 類；2=存在 1～2 類明顯問題；3=大致一致，僅細微問題；4=完全原生，熟練使用者信任每個頁面

### 5. 適應性

**檢查**：
- **拉伸的手機佈局**：平板/iPad 只放大手機介面，沒有使用 size classes / window size classes
- **方向損壞**：橫屏裁切、被忽略或無理由鎖定
- **鍵盤/IME 處理**：輸入框被鍵盤遮擋，沒有調整 inset
- **多工**：iPad Split View / Android 多視窗破壞佈局
- **摺疊屏**：Android 姿態變化時佈局不知道鉸鏈位置

**評分 0～4**：0=只支援一種螢幕尺寸；1=橫屏或平板嚴重損壞；2=部分支援；3=良好，僅邊緣問題；4=優秀，調整各種尺寸、方向和視窗模式

> 你可以讓我逐項執行、一次全部執行，或按你希望的任意順序執行。
>
> 修復後重新執行 `{{command_prefix}}impeccable audit`，檢視分數是否提高。

**重要要求**：全面但可執行。過多 P3 會製造噪音，應聚焦真正重要的問題。

**絕對不要**：
- 報告問題卻不解釋影響
- 提供泛泛建議，必須具體且可執行
- 跳過正面發現
- 忘記排優先順序，不可能所有問題都是 P0
- 未經驗證就報告誤報
