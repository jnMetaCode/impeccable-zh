> **还需要补充的上下文**：希望用户抵达的“顿悟时刻”，以及用户的经验水平。

尽快让用户第一次获得价值。新手引导的职责不是教授整个产品，而是带用户抵达那个足以证明产品值得投入时间的时刻。

## 评估新手引导需求

理解用户需要学习什么，以及为什么需要学习：

1. **识别挑战**：
   - 用户想完成什么？
   - 当前体验中哪些地方令人困惑或不清楚？
   - 用户会在哪里卡住或流失？
   - 希望用户抵达哪个“顿悟时刻”？

2. **理解用户**：
   - 他们的经验水平如何？（新手、熟练用户，还是两者都有？）
   - 他们的动机是什么？（兴奋地探索，还是工作要求？）
   - 他们愿意投入多少时间？（5 分钟，还是 30 分钟？）
   - 他们了解哪些替代方案？（从竞品迁移，还是第一次接触这个品类？）

3. **定义成功**：
   - 用户至少需要学会什么才能成功？
   - 希望他们完成哪个关键操作？（创建第一个项目，还是发出第一次邀请？）
   - 如何判断新手引导有效？（完成率，还是首次价值时间？）

**关键要求**：新手引导应让用户尽快获得价值，而不是尽可能教完所有内容。

## 新手引导原则

遵循以下核心原则：

### 展示，而不是讲解
- 使用可运行的示例演示，而不只是描述
- 在新手引导中提供真实功能，而不是单独的教程模式
- 使用渐进披露，一次只教一件事

### 尽可能允许跳过
- 让有经验的用户跳过新手引导
- 不要阻止用户进入产品
- 提供“跳过”或“我自己探索”选项

### 首次价值时间
- 尽快让用户抵达“顿悟时刻”
- 优先呈现最重要的概念
- 教会能带来 80% 价值的 20% 内容
- 将高级功能留到相关场景中再介绍

### 情境优先于仪式
- 在用户需要时教授功能，而不是一开始全部讲完
- 空状态就是新手引导机会
- 在使用位置提供工具提示和引导

### 尊重用户的理解力
- 不要居高临下或过度解释
- 保持简洁清楚
- 假设用户能够理解标准交互模式

## 设计新手引导体验

根据实际情境创建合适的引导：

### 产品首次引导

**欢迎页面**：
- 清晰的价值主张（这是什么产品？）
- 用户将学会或完成什么
- 诚实的时间预估
- 为有经验的用户提供跳过选项

**账户设置**：
- 只收集必需信息，其他内容稍后再收集
- 解释为什么需要每一项信息
- 尽可能提供合理默认值
- 在适当场景提供第三方账号登录

**核心概念介绍**：
- 介绍 1～3 个核心概念，而不是全部内容
- 使用简单语言和示例
- 尽可能让用户动手操作，而不是只阅读
- 显示进度，例如“第 1 步，共 3 步”

**第一次成功**：
- 引导用户完成一件真实的事情
- 提供预填充示例或模板
- 庆祝完成，但不要过度
- 给出清晰的下一步

### 功能发现与采用

**空状态**：
不要只留下空白，而应展示：
- 这里将出现什么（说明与截图或插图）
- 它为什么有价值
- 创建第一项内容的清晰行动按钮
- 示例或模板选项

示例：
```
还没有项目
项目可以帮助你组织工作并与团队协作。
[创建第一个项目] 或 [从模板开始]
```

**情境式工具提示**：
- 在合适时机出现，例如用户第一次看到该功能时
- 直接指向相关界面元素
- 提供简短说明和收益
- 可以关闭，并提供“不再显示”选项
- 可选的“了解更多”链接

**功能公告**：
- 新功能发布时突出显示
- 说明新增了什么，以及为什么重要
- 让用户能够立即尝试
- 可以关闭

**渐进式引导**：
- 在用户遇到功能时再讲解
- 为新增或未使用的功能提供徽标或标记
- 逐步开放复杂度，不要立刻展示所有选项

### 引导式导览与分步演示

**适用场景**：
- 功能众多的复杂界面
- 现有产品发生重大变化
- 需要行业领域知识的专业工具

**设计方式**：
- 聚焦特定界面元素，并调暗页面其他部分
- 保持步骤简短，每次导览最多 3～7 步
- 允许用户自由前后浏览步骤
- 提供“跳过导览”选项
- 可从帮助菜单重新播放

**最佳实践**：
- 交互优先于被动观看，让用户点击真实按钮
- 聚焦工作流而不是功能，例如“创建项目”而不是“这是项目按钮”
- 提供示例数据，确保操作能够真正运行

### 交互式教程

**适用场景**：
- 用户需要动手练习
- 概念复杂或陌生
- 风险较高，适合先在安全环境中练习

**设计方式**：
- 提供带示例数据的沙盒环境
- 给出清晰目标，例如“创建一张按地区展示销售额的图表”
- 提供分步指导
- 验证用户是否正确完成
- 设置明确的结业时刻，例如“你已经准备好了！”

### 文档与帮助

**产品内帮助**：
- 在整个界面中提供情境式帮助链接
- 提供键盘快捷键参考
- 提供可搜索的帮助中心
- 为复杂工作流提供视频教程

**帮助模式**：
- 在复杂功能附近放置 `?` 图标
- 在工具提示中提供“了解更多”链接
- 显示键盘快捷键提示，例如在搜索框中显示 `⌘K`

## 空状态设计

每个空状态都需要包含：

### 这里将出现什么
“你最近的项目会显示在这里”

### 为什么重要
“项目可以帮助你组织工作并与团队协作”

### 如何开始
[创建项目] 或 [从模板导入]

### 视觉吸引力
使用插图或图标，而不是只在空白页面上放文字

### 情境式帮助
“需要入门帮助？[观看 2 分钟教程]”

**空状态类型**：
- **首次使用**：从未使用过此功能，应强调价值并提供模板
- **用户已清空**：用户主动删除了全部内容，应轻量提示并方便重新创建
- **没有结果**：搜索或筛选没有返回内容，应建议其他关键词或清除筛选条件
- **没有权限**：无法访问，应解释原因和获取权限的方法
- **错误状态**：加载失败，应解释发生了什么并提供重试选项

## 实现模式

### 技术方案：

**工具提示库**：Tippy.js、Popper.js
**导览库**：Intro.js、Shepherd.js、React Joyride
**模态框模式**：焦点约束、背景遮罩、按 ESC 关闭
**进度记录**：使用 LocalStorage 保存“已看过”状态
**数据分析**：记录完成率和流失位置

**存储模式**：
```javascript
// 记录用户已经看过哪些新手引导步骤
localStorage.setItem('onboarding-completed', 'true');
localStorage.setItem('feature-tooltip-seen-reports', 'true');
```

**重要要求**：不要重复展示同一套新手引导，这会令人厌烦。记录完成状态并尊重用户的关闭操作。

**绝对不要**：
- 强迫用户完成很长的新手引导后才能使用产品
- 用显而易见的解释轻视用户
- 反复显示同一个工具提示，必须尊重关闭操作
- 在导览期间阻塞整个界面，应允许用户探索
- 创建与真实产品脱节的独立教程模式
- 一开始就塞入过多信息，应使用渐进披露
- 隐藏“跳过”或故意让它难以找到
- 忘记回访用户，不要再次展示首次引导

## 验证新手引导质量

与真实用户一起测试：

- **完成时间**：用户能否快速完成引导？
- **理解程度**：完成后用户是否真正理解？
- **后续行动**：用户是否执行了期望的下一步？
- **跳过率**：是否有太多用户跳过？也许引导太长或缺乏价值
- **完成率**：用户是否完成？如果完成率低，应进一步简化
- **首次价值时间**：用户需要多久才能第一次获得价值？
