# Shape

先弄清应该做什么以及它应该如何工作，再输出一份经过确认且不包含代码的设计简报。

## 阶段 1：探索访谈

此时不要编写代码，也不要选择视觉方向。

### 访谈节奏

- 有结构化提问工具时使用该工具，否则提问后停止并等待。
- 每轮询问两到三个相关问题，然后等待回答。默认只进行一轮；只有回答暴露出实质缺口时才增加第二轮。
- 不要一次抛出整份问卷、重复已经确定的事实，或把显而易见的事实变成选项。直接陈述最可能的理解，并邀请用户纠正。
- 信息稀少的请求至少需要一轮回答。非常精确的请求可能只需一次简短确认。

### 第 1 轮：目的、用户与结果

选择最可能改变结果的两到三个问题：

- 这个界面或功能有什么用途，必须解决什么问题？
- 具体哪些人会来到这里？他们处于什么情境和心理状态？
- 他们最需要理解或完成什么？成功是什么样子？
- 这里有哪些事实是相邻产品或通用模板无法声称的？

### 第 2 轮：素材、行为与边界

仅在仍有重大决策未解决时进行：

- 体验必须承载哪些真实内容、证据、数据和资源？现实的最小、典型和最大范围分别是多少？
- 哪些状态和转换很重要：首次使用、空、加载、错误、成功、权限、溢出，还是专家使用？
- 预期的保真度、广度和交互性是什么：探索、可投产页面、完整流程，还是更广的界面范围？
- 哪些内容必须保持不变？即使视觉精美，出现什么仍会让结果感觉错误？
- 哪些平台、框架、性能、无障碍、本地化或交付约束具有强制性？

绝不要询问 CSS 数值或套装式审美路线。视觉世界和概念选择属于 New-work。

## 阶段 2：确定设计方向

对于新界面、品牌扩展或替换，按照 [new-work.md](new-work.md) 完成视觉主导方向、必要的世界观工作坊和概念选择。复用探索结果，然后在进入契约、持久化或实现之前返回。在已有视觉世界中，只有当构图或交互仍有实质性开放空间时，才使用其中的概念流程。

## 阶段 3：编写简报

编写尽可能精简且有用的简报：

1. **任务与受众：** 谁会到达这里，他们的情境、需求和访客模式是什么。
2. **结果与证据：** 主要任务或操作、成功标准、真实证据和产品特有事实。
3. **选定方向：** 视觉主导方向、结构或交互主张、顺序、焦点时刻及其实现影响。
4. **范围与边界：** 保真度、广度、交互性、明确目标、必须保持不变的部分和显式反目标。
5. **状态与范围：** 现实的内容或数据范围，以及重要状态。
6. **交互与布局：** 层级、拓扑、响应式、可供性、反馈和转换；描述意图，而不是 CSS。
7. **约束与开放决策：** 平台、交付、无障碍、本地化、可复用组件，以及构建者不得自行发明的选择。

任务已经明确时使用三到五个要点；只有面对模糊、多页面或独立规划任务时才使用完整结构。不要重复复述对话。

## 确认并停止

提交简报以获得明确确认，或进行一轮修正，然后停止：shape 绝不编写代码或方向契约。

当没有人工回答或结构化回答机制时，清楚标记假设，返回简报，然后停止。
