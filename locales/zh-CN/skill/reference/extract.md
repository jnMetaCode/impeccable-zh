# Extract 流程

识别可复用模式、组件和设计 token，再将它们提取并整合进设计系统，以便系统性复用。

## 步骤 1：发现设计系统

找到设计系统、组件库或共享 UI 目录。了解其结构：组件组织方式、命名惯例、设计 token 结构和导入导出惯例。

**关键要求**：如果不存在设计系统，暂时不要创建。{{ask_instruction}} 先了解首选位置和结构。

## 步骤 2：识别模式

在目标区域中寻找适合提取的内容：

- **重复组件**：使用三次以上的相似 UI 模式，例如按钮、卡片和输入框
- **硬编码值**：应成为 token 的颜色、间距、排版和阴影
- **不一致的变体**：同一概念存在多种实现
- **组合模式**：重复出现的布局或交互模式，例如表单行、工具栏分组和空状态
- **文字样式**：重复出现的字号、字重与行高组合
- **动画模式**：重复出现的缓动、时长或关键帧组合

评估价值：只有同一意图下使用三次以上的内容才应提取。过早抽象比重复更糟。

## 步骤 3：规划提取

制定系统化计划：

- **要提取的组件**：哪些界面元素应成为可复用组件？
- **要创建的 token**：哪些硬编码值应成为设计 token？
- **需要支持的变体**：每个组件需要哪些变化形式？
- **命名惯例**：符合现有模式的组件名、token 名和 prop 名
- **迁移路径**：如何重构现有用法，使其改用新的共享版本

**重要要求**：设计系统应逐步成长。只提取现在已经明确可复用的内容，而不是所有未来可能复用的内容。

## 步骤 4：提取并增强

构建经过改进的可复用版本：

- **组件**：清晰的 props API、合理默认值、适用于不同场景的正确变体、内置无障碍能力（ARIA、键盘导航、焦点管理），以及文档和使用示例
- **设计 token**：清晰命名（基础 token 与语义 token）、正确层级和组织方式，以及每个 token 的使用说明
- **模式**：何时使用该模式、代码示例、变体与组合方式

## 步骤 5：迁移

用新的共享版本替换现有用法：

- **找到全部实例**：搜索已提取模式的所有用法
- **系统性替换**：更新每处用法，使其使用共享版本
- **充分测试**：确保视觉和功能一致
- **删除死代码**：移除旧实现

## 步骤 6：编写文档

更新设计系统文档：

- 将新组件加入组件库
- 记录 token 的用途和值
- 添加示例和使用指南
- 更新 Storybook 或组件目录

**绝对不要**：
- 未经泛化就提取一次性、特定情境的实现
- 创建泛化到失去用途的组件
- 不考虑现有设计系统惯例就提取
- 省略正确的 TypeScript 类型或 prop 文档
- 为每一个值都创建 token，token 必须具有语义
- 提取意图不同的内容，两个外观相似但用途不同的按钮应继续分开
