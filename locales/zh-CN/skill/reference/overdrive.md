响应必须以下列内容开头：

```
──────────── ⚡ OVERDRIVE ─────────────
》》》 Entering overdrive mode...
```

把界面推向常规边界之外。这不只是添加视觉效果，而是充分利用浏览器能力，让界面的任何部分都显得非凡：能处理百万行的表格、从触发按钮形变而来的对话框、用流式反馈实时校验的表单，或具有电影感的页面转换。

**本命令格外重要的原则**：上下文决定“非凡”的含义。作品集上的粒子系统可能令人惊艳，设置页面上的同一效果却会令人尴尬；但设置页面如果拥有即时乐观保存和动画状态转换，同样可以非凡。决定方案前先理解项目个性和目标。

### 构建前先提出方案

本命令最容易方向失误。绝不要直接实现。必须：

1. **思考 2～3 个不同方向**：考虑不同技术、野心程度和审美方式；简要说明每个方向最终的观感。
2. **写代码前取得用户选择。** {{ask_instruction}} 每个选项本身必须包含方向说明和取舍（浏览器支持、性能成本、复杂度），让用户能阅读后选择。结构化问题会阻塞同一条消息，直到用户回答；与问题并列编写的方向在选择期间不可见。
3. 只实施用户确认的方向。

跳过这一步可能构建出令人尴尬、只能丢弃的结果。

### 使用浏览器自动化迭代

技术上有野心的效果几乎不会第一次就正确。必须主动使用浏览器自动化预览、视觉验证并迭代。不要假设效果正确，要亲自检查，并预期多轮精修。“技术可运行”和“视觉非凡”之间的差距只能通过视觉迭代弥合，不能只靠代码。

## 判断这里的“非凡”是什么

正确的技术野心完全取决于当前对象。选择技术前先问：**什么会让这个特定界面的用户说“哇，真不错”？**

### 视觉或营销界面
页面、Hero、落地页和作品集的惊艳通常来自感官体验：滚动驱动揭示、着色器背景、电影式页面转换、响应光标的生成艺术。

### 功能型界面
表格、表单、对话框和导航的惊艳在于操作感受：通过 View Transitions 从按钮形变而来的对话框、借助虚拟滚动以 60fps 渲染十万行的数据表、近乎即时的流式校验、具有弹簧物理效果的拖放。

### 性能关键界面
惊艳不可见但可以感受：搜索五万项仍毫无闪烁、复杂表单从不阻塞主线程、近实时处理的图片编辑器。界面从不迟疑。

### 数据密集界面
图表与仪表盘的惊艳来自流动性：Canvas/WebGL GPU 渲染海量数据、数据状态之间的动画转换、自然稳定的力导向图。

**共同点**：实现超出用户对 Web 界面的预期。技术服务于体验，而不是反过来。

## 工具箱

按目标组织，而不是按技术名称组织。

### 让转换具有电影感
- **View Transitions API**（同文档：全部浏览器；跨文档：Firefox 不支持）：状态间共享元素形变，例如列表项展开成详情页、按钮变为对话框；最接近原生 FLIP 动画。
- **`@starting-style`**（全部浏览器）：只用 CSS 让元素从 `display: none` 进入可见状态，包括入场关键帧。
- **弹簧物理**：使用质量、张力和阻尼，而不是 cubic-bezier。可使用 motion（原 Framer Motion）、GSAP 或自行实现弹簧求解器。

### 将动画绑定到滚动位置
- **滚动驱动动画**（`animation-timeline: scroll()`）：纯 CSS，无需 JS。视差、进度条和揭示序列由滚动位置驱动。（Chrome/Edge/Safari；Firefox 仅 flag；始终提供静态回退）

### 超越 CSS 渲染
- **WebGL**（全部浏览器）：着色器、后处理和粒子系统。可使用 Three.js、轻量 OGL、regl。
- **WebGPU**（Chrome/Edge；Safari 26+；Windows/macOS 上的 Firefox，Linux/Android Firefox 仅 flag）：新一代 GPU 计算，能力强于 WebGL。始终回退到 WebGL2。
- **Canvas 2D / OffscreenCanvas**：自定义渲染、像素处理，或通过 Web Worker + OffscreenCanvas 把繁重渲染移出主线程。
- **SVG filter chain**：用 displacement map、turbulence、morphology 实现有机扭曲，且可由 CSS 动画化。

### 让数据鲜活
- **虚拟滚动**：数万项表格或列表只渲染可见行。简单情况无需库，复杂情况使用 TanStack Virtual。
- **GPU 加速图表**：为大到无法用 SVG/DOM 渲染的数据集使用 Canvas 或 WebGL，可使用 deck.gl 或基于 regl 的自定义渲染器。
- **数据转换动画**：在图表状态间形变，而不是直接替换。使用 D3 `transition()` 或面向 DOM 图表的 View Transitions。

### 动画化复杂属性
- **`@property`**（全部浏览器）：注册有类型的 CSS 自定义属性，让渐变、颜色和复杂值可以插值动画。
- **Web Animations API**（全部浏览器）：用 JavaScript 驱动、具备 CSS 性能的动画，可组合、取消和反向，是复杂编排的基础。

### 突破性能边界
- **Web Worker**：把数据处理、图片操作和搜索索引等繁重计算移出主线程。
- **OffscreenCanvas**：在 Worker 线程渲染，让复杂视觉运行时主线程仍保持空闲。
- **WASM**：为图片处理、物理模拟和编解码等计算密集功能提供接近原生的性能。

### 与设备交互
- **Web Audio API**：空间音频、音频响应视觉和声音反馈，需要用户手势后启动。
- **设备 API**：方向、环境光和地理位置。谨慎使用，始终取得用户许可。

**注意**：本命令增强界面的感受，不改变产品功能。实时协作、离线支持和新后端能力属于产品决策，不是 UI 增强。聚焦于让现有功能显得非凡。

## 有纪律地实现

### 渐进增强不可妥协

每项技术都必须优雅降级。没有增强效果时，体验仍然必须良好。

```css
@supports (animation-timeline: scroll()) {
  .hero { animation-timeline: scroll(); }
}
```

```javascript
if ('gpu' in navigator) { /* WebGPU */ }
else if (canvas.getContext('webgl2')) { /* WebGL2 fallback */ }
/* CSS-only fallback must still look good */
```

### 性能规则

- 目标为 60fps；低于 50 时简化。
- WebGL context、WASM module 等繁重资源只在接近视口时延迟初始化。
- 暂停视口外渲染；看不见的内容应停止运行。
- 在真实中端设备上测试，而不只是在开发机器上。

### 精修决定差异

“酷”和“非凡”之间的差距在最后 20% 的精修：弹簧动画的缓动曲线、错峰揭示的时间偏移、让转换具有物理感的细微辅助运动。不要发布第一个可运行版本，要发布感觉顺理成章的版本。

**绝对不要**：
- 发布会让中端设备卡顿的效果
- 使用前沿 API 却不提供可用回退
- 未经用户明确同意添加声音
- 用技术野心掩盖薄弱的设计基础，应先用其他命令修复基础
- 叠加多个相互竞争的非凡时刻；聚焦创造影响力，过量制造噪音

## 验证结果

- **惊艳测试**：展示给未看过的人，他们有反应吗？
- **移除测试**：去掉效果后，体验是否明显减弱，还是无人察觉？
- **设备测试**：在手机、平板和 Chromebook 上运行，仍然流畅吗？
- **情境测试**：它符合这个品牌和受众吗？

“技术上非凡”不是使用最新 API，而是让界面做到用户原以为网站做不到的事情。
