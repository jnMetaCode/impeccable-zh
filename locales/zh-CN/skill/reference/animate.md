> **还需要补充的上下文**：性能约束。

用动效解释状态、关系和层级，或创造一个界面确实值得拥有的编排时刻。没有目的的装饰会形成动画债务。

## 访客模式

- **Persuade + Experience：** 动效可以承载语气。优先编排一个经过设计的焦点序列，而不是让每个区块重复揭示。
- **Operate + Read：** 动效服务于反馈、状态和连续性。日常过渡要快，不要让用户等待页面加载编排。
- **原生平台（`ios` / `android` / `adaptive`）：** 遵循 [ios.md](ios.md) 或 [android.md](android.md) 的 Motion 部分，包括平台的“减少动态效果”行为。不要使用下述 Web 工具。

## 找到任务

检查现有动效语言、交互状态、目标设备和性能预算。只在动效能够完成以下任务时使用：

- 确认一项操作；
- 让状态变化或空间关系易于理解；
- 在导航或布局变化时保持连续性；
- 在有意义的时刻引导注意力；
- 体现所选视觉世界。

只有无法推断重要约束时才询问。不要仅仅因为某个静态区域存在，就给它添加动画。

## 确立动效主张

实现前先写一份简短计划：

- **焦点时刻：** 唯一值得特别编排的序列或交互（如果存在）。
- **连续性：** 需要解释的状态、布局或导航变化。
- **反馈：** 需要确认的控件和结果。
- **预算：** 哪些效果可能昂贵，以及运行频率。

焦点时刻必须来自当前产品和界面概念。通用的淡入上移、悬停抬升、视差层或滚动揭示不构成动效主张。

## 根据含义选择材质

transform 和 opacity 是可靠基础，但不是全部工具。根据转换所表达的内容选择属性：

- **连续性与关系：** 共享元素动效、FLIP 式 transform、视图转换或有意的空间移动。
- **焦点与纵深：** 有边界的模糊、滤镜、背景效果、光线或阴影变化。
- **揭示与构图：** 遮罩、裁剪路径、裁切或受控遮挡。
- **材质与能量：** 当视觉世界和运行时支持时，使用颜色、渐变位置、纹理、扭曲或着色器效果。
- **状态与反馈：** 使用能让因果关系清楚无误的最小变化。

不要为了炫技叠加多种技术。一个强有力的材质概念贯穿焦点序列和安静的辅助状态，通常已经足够。

当列表确实以列表形式出现时，可以对同级项目使用错峰动画。限制总延迟，绝不要把滚动经过的每个区块都重新解释为错峰列表。

## 时长与缓动

时长应表达距离和结果的重要性：

| 时长 | 典型用途 |
|---|---|
| 100～150ms | 即时反馈 |
| 150～300ms | 日常状态变化 |
| 300～500ms | 布局、浮层或视图转换 |
| 500～800ms | 经过有意编排的焦点入场 |

退出应快于进入。自信入场可使用 `cubic-bezier(0.16, 1, 0.3, 1)` 这类自然减速；不要条件反射地使用弹跳或弹性曲线。过长的反馈会让人感觉延迟。

## 按运行时实现

- 声明式状态和有限序列使用 CSS transition 和 keyframes。
- 需要中断、编排和动态值时，使用 Web Animations API 或项目现有动效库。
- 当重点是跨状态连续性时，使用 View Transitions 或共享元素技术。
- 只有滚动关系本身具有含义时才使用滚动驱动动效，并提供可靠回退。
- 现有技术栈能清晰实现的效果，不要为它增加新依赖。

让内容在默认状态下可见，避免脚本失败时页面内容消失。不要随意动画化 `width`、`height`、`top`、`left` 和 margin 等驱动布局的属性；适当使用 FLIP、transform 或 grid 技术。把模糊、滤镜、阴影、canvas 和着色器限制在隔离区域。仅在确定会执行动画时应用 `will-change`。在目标视口和设备上测量，不要假设使用 transform 就一定快。

## 无障碍与控制

尊重自动播放和声音偏好。任何非必要循环在离开视口或隐藏时都必须停止。

每个 Web 动画都需要一条经过设计的 `prefers-reduced-motion` 路径。移除或减弱空间移动，同时保留能传达含义的透明度、颜色和状态转换。减少动态效果意味着动画更少、更温和，而不是禁用全部动效；确认操作的反馈仍应清晰可见。

## 验证

- 焦点动效属于所选视觉世界和当前界面。
- 每项辅助动画都在解释反馈、状态或关系。
- 中断和重复使用时行为正确。
- 桌面、移动端和键盘路径保持可用。
- `prefers-reduced-motion` 路径能减少运动，同时不抹去有意义的反馈或状态变化。
- 昂贵效果在目标设备上保持流畅。
- 移除某项动画会损失含义或创作个性，而不只是减少装饰。

动效的存在有充分理由后，交给 `{{command_prefix}}impeccable polish` 完成最终精修。
