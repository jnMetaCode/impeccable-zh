# 中文 UX 文案增强

> 来源类型：`jnMetaCode-original`。
> 适用命令：`clarify`、`harden`。

通用 UX 写作规则之外，中文产品必须额外检查以下问题。

## 按钮与操作

- 优先使用“动词 + 对象”：`保存草稿`、`删除成员`、`提交审核`。
- 上下文已经明确对象时可以只保留动词：表单底部的 `保存`。
- 避免含义不完整的 `确定`、`提交`、`处理`、`操作`。
- 同一个动作不要混用 `新建`、`创建`、`添加`；根据产品术语选择一个并保持一致。
- 按钮文案描述结果，不描述点击动作。使用 `下载报告`，不使用 `点击下载`。

## 错误与恢复

错误信息按“发生了什么 + 用户能做什么”组织：

```text
无法保存修改。网络连接已中断，请恢复网络后重试。
```

避免：

- `操作失败`：没有说明失败对象；
- `系统繁忙，请稍后再试`：系统无法确认原因时不要假装知道；
- `参数错误`：把内部实现语言直接交给用户；
- `未知错误`：没有恢复路径；
- 把完整异常、堆栈、请求 ID 当作主要信息。

请求 ID 可以放在“错误详情”中，供支持人员使用。

## 高风险确认

删除、支付、发布、转账、权限变更和退出组织必须说明：

1. 操作对象；
2. 是否可恢复；
3. 立即生效还是延迟生效；
4. 用户下一步需要做什么。

```text
删除“华东销售组”？
该小组及其未导出的报表将永久删除，无法恢复。

[取消] [删除小组]
```

不要使用：

```text
确认执行此操作吗？
[否] [是]
```

## 金额、日期与数量

- 金额必须明确币种；跨币种场景不要只显示 `¥`。
- 千分位、小数位和负数格式使用 locale formatter，不能拼接字符串。
- `今天`、`刚刚` 等相对时间需要可访问的绝对时间或详情。
- 有时区影响的操作明确显示时区。
- 中文通常不依赖名词复数，但数量单位和量词仍需符合语境。
- 不把 `1.2k`、`3m` 等英文缩写机械带入正式中文业务界面。

## 空状态

先区分空状态原因：

- 首次使用：解释价值并提供创建入口；
- 搜索无结果：展示查询条件并允许清除；
- 筛选后无数据：提供重置筛选；
- 无权限：说明需要什么权限和申请路径；
- 加载失败：展示重试或替代路径；
- 数据确实为空：不伪装成错误。

避免所有场景都使用“暂无数据”。

## 避免翻译腔

- `了解更多关于此功能的信息` → `了解此功能`
- `你的更改已被成功保存` → `修改已保存`
- `你确定你想要继续吗？` → 根据实际后果重写
- `发生了一个错误` → 说明失败对象和恢复方式
- `请输入您的用户名` → 语境允许时使用 `输入用户名`

不要为了口语化删除事实，也不要把严肃风险写成玩笑。

## 验证样例

至少使用以下动态内容检查界面：

- 20 字以上的中文姓名或组织名；
- `新疆维吾尔自治区` 等长地区名；
- `人民币 1,234,567.89 元`；
- 包含英文产品名、版本号和中文单位的句子；
- 0、1、2、10,000 等数量边界；
- 失败、无权限、处理中、部分成功和需要人工审核状态；
- 简体中文、繁体中文和英文切换后的布局。

最终文案必须经完整流程阅读，不能只在字符串列表里逐项润色。
